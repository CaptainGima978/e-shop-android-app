# Μη Λειτουργικές Απαιτήσεις

### Απόδοση (Perfornance)

- Οι κατάλογοι των εξαρτημάτων πρέπει να φορτώνονται σε ικανοποιητικό χρόνο, ακόμα και με μεγάλο πλήθος εγγραφών.
- Η ενημέρωση των καταλόγων (εξαρτημάτων ή συνθέσεων) γίνεται σε πραγματικό χρόνο και οι αλλαγές είναι άμεσα διαθέσιμες στους χρήστες.

### Αξιοπιστία (Reliability)

- Η εφαρμογή πρέπει να διαχειρίζεται περιπτώσεις δικτύου (offline mode, timeouts) και να διαχειρίζεται κατάλληλα τις περιπτώσεις λάθους αν ο server δεν είναι διαθέσιμος.
- Τα δεδομένα των χρηστών (στοιχεία λογαριασμού, αποθηκευμένες συνθέσεις) θα αποθηκεύονται αξιόπιστα στη βάση (cloud storage, backups)

### Χρηστικότητα (Usability)

- Το UI θα είναι σαφές και λειτουργικό, σχεδιασμένο για χρήση σε κινητό.
- Η διαδικασία της σύνθεσης θα είναι εύκολη με απλά βήματα για τον χρήστη.

### Ασφάλεια (Security)

- Τα ευαίσθητα δεδομένα (κωδικοί, στοιχεία παραγγελίας/ πληρωμής) θα προστατεύονται. Θα αποθηκεύονται κρυπτογραφημένα, όταν αυτό χρειάζεται.
- Η πρόσβαση στα εργαλεία της ομάδας διαχείρισης (αποδοχή παραγγελιών κλπ) θα φυλάσσεται με ελέγχους ταυτότητας.

### Συμβατότητα (Compatibility)

- Η εφαρμογή θα υποστηρίζεται από συσκευές Android, ενώ θα λειτουργεί τόσο σε κινητά όσο και σε ταμπλετ χωρίς loss of fanctionality.

### Επεκτασιμοτητα (Scalability)

- Η αρχιτεκτονική του προγράμματος θα επιτρέπει την επέκταση του λογισμικού χωρίς να απαιτεί αλλαγές στα βασικά κομμάτια του κώδικα. (π.χ. προσθήκη νέων προϊόντων ή εξαρτημάτων όπως Monitors, πληκτρολόγια κλπ)
- Η βάση θα είναι σχεδιασμένη να υποστηρίξει μεγάλο αριθμό εξαρτημάτων, συνθέσεων αλλά και νέων χρηστών.

### Συντηρησιμότητα (Maintainability)

- Ο κώδικας θα υποβάλλεται σε ελέγχους ποιότητας λογισμικού (JUnit tests, Code Coverage Reports).
- Ο κώδικας θα τεκμηριώνεται με JavaDoc comments και συνοδευτικά markdown αρχεία.
- Ο κώδικας θα ακολουθεί πρότυπα clean code πρακτικών
- Θα υπάρχουν επαρκείς οδηγίες εγκατάστασης και χρήσης τόσο για τον τελικό χρήστη όσο και για νέους developers της ομάδας ανάπτυξης του λογισμικού.
